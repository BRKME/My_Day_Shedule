# План рефакторинга 04.08.2026

Аудит выявил 7 проблем. Правим все, поведение бота не меняем ни на байт.

## Инвариант всего рефакторинга

Текст сообщений, порядок задач и их индексы **не меняются**. `tracker_bot`
хранит прогресс по индексам строк — любой сдвиг ломает уже отправленные
сообщения. Каждый шаг проверяется тестом на эквивалентность со снапшотом.

## Порядок (RED → GREEN → REFACTOR на каждом)

1. Снапшот текущего расписания в `/tmp` — эталон эквивалентности ✔
2. `tests/test_core.py` (RED) → `core.py` (GREEN)
3. Перевести `notifier.py` и `tracker_bot.py` на `core` с ре-экспортом имён
   (внешние импорты в существующих тестах не должны сломаться)
4. `tests/test_schedule_data.py` (RED) → загрузка расписания из `data/`
5. `tests/test_state_prune.py` (RED) → прополка состояний
6. Чистка: `Procfile`, `render.yaml`, `requirements.txt`, workflow, `README.md`
7. Верификация: полный прогон тестов + smoke-рендер утреннего/вечернего
   сообщения до и после — тексты должны совпасть

## Что НЕ делаем (YAGNI)

- Не разбиваем `TaskTrackerBot` на классы — 53 метода на живом проде без
  интеграционных тестов режутся не рефакторингом, а инцидентом. Сначала
  тесты на ядро (эта итерация), декомпозиция — следующей.
- Не переписываем историю git (`.git` 17 МБ). Прополка останавливает рост;
  сжатие истории — отдельное решение с force-push, см. README.
- Не переносим расписание в YAML: на VPS `systemd`-сервис поднят на голом
  окружении, PyYAML там может не оказаться, и утреннее сообщение упадёт.
  JSON — stdlib, нулевой риск деплоя.
